# 限制链接元数据流量

## Goal

阻止链接预览在自动抓取网页标题和站点图标时完整下载大文件，确保单条剪贴板链接产生的后台响应体流量始终受硬上限约束。

## Requirements

- 链接页面正文必须采用可取消的流式读取，不得先完整下载再检查大小。
- 单个页面正文最多读取 512 KiB；已知 `Content-Length` 超限时应在读取正文前拒绝。
- 页面响应声明 MIME 类型时，仅接受 HTML/XHTML；未知 MIME 类型可在字节上限内兼容处理。
- 单个站点图标最多读取 256 KiB，且每个页面最多尝试 4 个图标候选（包含 `/favicon.ico` 回退）。
- 图标响应声明 MIME 类型时，仅接受图片或现有兼容的 `application/octet-stream`。
- 达到正文上限、任务取消、超时或响应不合格时必须停止对应网络任务，且不得保存不完整图标数据。
- 同一 `contentHash` 的并发元数据请求只允许一个在途任务，避免捕获路径和列表补抓路径重复下载。
- `Link Display Mode` 为 `plain` 时，新捕获链接和历史补抓都不得发起元数据网络请求。
- 保持现有富链接标题、favicon 和持久化行为；不修改 SwiftData/CloudKit 模型，不引入第三方依赖。

## Acceptance Criteria

- [x] 忽略 `Range` 且返回超大或无限分块正文的测试服务器，最多只能向客户端交付 512 KiB 加一个边界检测字节，随后任务被取消。
- [x] 已知 `Content-Length` 超过页面或图标上限时，不消费响应体并返回无元数据结果。
- [x] 非 HTML 页面不会被解析为标题；超大图标不会被保存。
- [x] 单页图标请求次数不超过 4，单次图标正文不超过 256 KiB。
- [x] 同一 hash 的两个并发调用只触发一次元数据抓取。
- [x] `plain` 模式下，捕获新 URL 与加载缺失元数据的历史记录均不会调用元数据引擎。
- [x] 正常小型 HTML 页面仍能解析标题并保存有效 favicon。
- [x] 新增的定向回归测试通过，完整 macOS Debug 构建通过。

## Notes

- 本次不持久化失败/退避状态；硬流量上限与在途去重已能消除当前高流量风险，避免为此引入数据模型迁移。
- 不记录完整 URL，避免日志泄露剪贴板隐私。
