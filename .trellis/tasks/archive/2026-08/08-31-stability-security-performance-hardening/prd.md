# 修复稳定性、安全与性能问题

## Goal

修复 v2.1.8–v2.2.10 审计中发现的卡顿、内存压力崩溃、存储切换竞态、安全漏洞和高耦合热路径，同时保持现有剪贴板、iCloud、屏幕贴图、富链接和 AI 功能的用户行为及已有数据兼容。

## Assumptions

- 本任务覆盖审计报告中列出的全部高优先级问题和直接相关的中优先级问题。
- 不引入第三方依赖，不改变 macOS 14 最低部署版本，不修改 CloudKit 容器标识。
- 富链接仍可自动抓取，但只能访问经过完整地址校验的公网目标，并继续遵守现有 plain/rich 偏好。
- 无法安全处理的超大图片宁可作为普通文件记录或跳过昂贵派生处理，也不能无界读取、解码或 OCR。
- 持久化存储不可用时应用必须保持可启动，并向用户暴露降级状态；不能因可恢复的文件、权限或数据库错误直接退出。

## Requirements

### R1 — 有界图片采集、贴图和 OCR

- 文件图片不得在 `@MainActor` 上使用 `Data(contentsOf:)` 或累积整个文件后再下采样。
- 所有图片入口都必须有统一的编码字节、像素尺寸和解码像素预算。
- 屏幕贴图和缩略图必须从文件 URL 直接使用 ImageIO 后台下采样。
- OCR 必须使用有界下采样图像，取消后不得继续发布或写回结果。
- 超出预算的文件图片必须退化为普通文件记录；超出预算的内存图片不得触发 OCR 或全尺寸派生任务。

### R2 — 事务化存储路由切换

- 一次剪贴板捕获必须固定使用同一个 `StorageManager`，不得在多个 `await` 之间重新解析全局路由。
- 切换本地/iCloud 前必须停止采集、等待在途持久化和目标存储任务排空，再导出或激活新路由。
- 重置 iCloud 本地缓存前必须取消关联维护任务、关闭旧存储任务并释放旧容器引用，之后才能删除 SQLite artifacts。
- 路由切换失败必须恢复一致的偏好、当前路由和监控状态。

### R3 — 有界跨库存储合并和维护

- 跨路由合并不得一次性物化全部记录及所有 external-storage blob；记录必须以固定上限批次导出和导入。
- 批次合并必须保持现有 `contentHash` 去重、收藏逻辑 OR、分组和大文本兼容语义。
- 重复记录修复和升级维护必须真正分页，避免注释声称分页但实现全表 fetch。
- 主线程上的图标修复必须分批让出执行权，昂贵的颜色分析移出 SwiftUI 渲染路径。

### R4 — 可恢复启动和屏幕安全降级

- 本地/Cloud 持久化初始化失败时不得因可恢复错误调用 `fatalError`；应降级到可用的本地或内存运行时并记录用户可见错误。
- 面板定位不得强制解包 `NSScreen.main`；显示器暂不可用时应安全地推迟显示。

### R5 — AI 密钥和 endpoint 安全

- API Key 必须存入 macOS Keychain，UserDefaults 和 Codable 配置不得再持久化明文密钥。
- 首次加载旧配置时必须迁移已有明文密钥；只有 Keychain 写入成功后才能清除旧持久化值。
- 删除配置时必须删除对应 Keychain 项。
- AI endpoint 仅允许 HTTPS；显式 loopback 开发地址可以使用 HTTP，其他明文地址必须被拒绝。

### R6 — 富链接 SSRF 防护

- 初始 URL、favicon URL 和每次重定向都必须同时校验 scheme、主机和解析后的地址。
- 必须拒绝回环、私网、link-local、CGNAT、文档/保留、组播以及 IPv4-mapped IPv6 等非公网目标。
- DNS 校验必须在后台执行；不得阻塞 MainActor。
- 现有响应字节、MIME、候选数、并发和取消上限必须继续成立。

### R7 — SwiftUI 渲染与状态边界

- 卡片 `body` 不得计算图片主色，也不得为每张可见卡片单独读取数据库。
- 图标主色必须包含在轻量快照/`ClipboardItem` 中，视图只做常量时间颜色转换。
- 行/卡片不得因 quick look、拖拽或其他无关面板状态而全部失效；共享状态改用 Observation 或等价的窄依赖边界。
- 列表滚动请求不得增加无条件的 `DispatchQueue.main.async` 一帧延迟。

### R8 — 可取消且 Sendable 的搜索

- 搜索过滤必须使用可取消的 Swift concurrency Task，查询或作用域变化后旧 CPU 工作应尽快结束。
- 后台过滤只能携带纯 `Sendable` 快照；`NSImage`、SwiftUI `Color` 和其他 UI 类型不得跨执行器。
- 数据库补充搜索现有 ID/hash 去重和 generation 语义必须保持。

### R9 — 元数据任务生命周期

- 缺失链接元数据的排队标记必须在成功、失败和取消时清除，且失败重试应有有界退避。
- 不得形成随会话永久增长的 pending hash 集合。

### R10 — 兼容性与诊断

- 已有本地和 iCloud 数据无需用户手工迁移；收藏、分组、大文本、RTF、图片和来源信息不得丢失。
- 新增拒绝、降级和迁移路径必须提供不包含剪贴板正文、完整 URL 或 API Key 的诊断信息。
- 不新增无关功能或第三方框架。

### R11 — 大文件模块化边界

- `clipaste/` 与 `scripts/` 下的手写 Swift 文件原则上不得超过 300 行；拆分必须按职责、数据边界或独立视图/服务完成，不能只按行号机械切片。
- `StorageManager`、`ClipboardRuntimeStore`、`MigrationManager` 等高耦合核心必须拆成可辨识的 facade、生命周期、查询、迁移、维护和 actor 扩展文件。
- SwiftUI 大视图必须把独立页面、区域和辅助组件提取为独立文件；共享状态所有权保持唯一，不能因拆分复制状态或业务逻辑。
- 若确有 Swift 宏、生成代码或作用域限制导致无法低于 300 行，必须在自动检查的显式白名单中记录文件、原因和复核条件；默认白名单为空。
- 新增自动化守门测试，任何未声明豁免的 Swift 文件超过 300 行都必须失败。

## Acceptance Criteria

- [x] 超大文件图片测试证明不会把整个文件读入 `Data`，并会退化为普通文件记录或有界缩略图。
- [x] OCR 测试证明输入会按硬像素上限下采样，取消后不写回结果。
- [x] 存储切换测试证明捕获任务固定源存储、切换等待 drain，旧路由任务不能写入新路由。
- [x] iCloud 缓存重置测试证明旧存储 shutdown/释放发生在 artifact 删除前。
- [x] 跨库合并压力测试使用多批记录，峰值载荷受批次上限控制，并保持合并语义。
- [x] 持久化初始化失败测试证明应用进入降级运行时而不是触发 `fatalError`。
- [x] AI 配置迁移测试证明 UserDefaults 中不再出现 API Key，Keychain 读写/删除及失败保留旧值均正确。
- [x] endpoint 测试覆盖 HTTPS、loopback HTTP 和非 loopback HTTP 拒绝。
- [x] SSRF 测试覆盖 IPv4/IPv6 私网、link-local、CGNAT、映射地址、恶意 DNS 解析和重定向；现有流量测试继续通过。
- [x] 卡片不再执行逐行主色数据库查询或在 `body` 中分析 NSImage。
- [x] 搜索压力测试证明旧过滤 Task 可取消，且后台输入为纯 `Sendable` 数据。
- [x] 重复修复、链接 pending 生命周期和纵向滚动的回归测试通过。
- [x] 使用完整并发检查对修改范围执行类型检查，无新增 warning。
- [x] 现有 7 组定向回归脚本及新增测试全部通过。
- [x] macOS Debug clean build 成功，`git diff --check` 通过。
- [x] 文件规模守门测试证明 `clipaste/` 与 `scripts/` 下没有未豁免的 300 行以上 Swift 文件。
- [x] 拆分后的存储、运行时、迁移、ViewModel、服务和 SwiftUI 组件保持原行为，完整回归与严格并发构建通过。

## Out of Scope

- 重写全部 SwiftData schema 或更换持久化框架。
- 更改 CloudKit 容器、同步产品策略或剪贴板保留策略。
- 引入第三方网络、Keychain、图片或状态管理依赖。
- 与上述风险无关的 UI 视觉改版和代码格式化。
