# 屏幕贴图与拖拽兼容

## Goal

允许用户从 Clipaste 历史记录中拖出内容，在屏幕任意位置松开后将其作为始终可见的贴图窗口，同时保留现有“拖拽到其他应用以插入或粘贴”的能力，避免两种意图误触。

## Background

- 水平卡片和纵向列表均通过 SwiftUI `.onDrag` 返回 `ClipboardItem.universalDragProvider`。
- 现有 provider 按内容类型对外提供文件 URL、图片数据、URL 和纯文本，并额外注册 Clipaste 内部 item ID。
- 内部 item ID 当前用于将历史记录拖到收藏或自定义分组。
- Finder 桌面、文档编辑器、聊天应用等目标可能本身接收同一份拖拽数据，因此“拖拽操作是否为 `.none`”不能单独作为贴屏意图的可靠判据。
- SwiftUI `.onDrag` 可创建 provider 和预览，但现有代码没有拖拽会话结束的坐标、目标和 operation 回调。
- 当前历史面板使用高窗口层级的 `NSPanel`，贴图窗口需要独立管理，不能复用历史面板的显隐生命周期。
- 高级设置已使用持久化偏好控制交互与界面能力，贴图开关应沿用同一展示形式。
- 项目 String Catalog 的源语言为英语，现有应用语言为英语、简体中文、繁体中文、日语、韩语、德语和法语。

## Requirements

- 现有拖拽到第三方应用、Finder 和 Clipaste 分组的行为不得回归。
- 卡片和纵向列表使用左侧来源应用图标作为“贴到屏幕”的专用拖拽区域；拖动记录其他区域继续执行现有对外拖拽。
- 贴图功能在高级设置中提供 Toggle，用户可自主启用或关闭。
- 高级设置提供贴图初始尺寸比例，范围为原图的 25%–100%、步进 5%，默认 100%。
- 贴图功能默认关闭；已有用户升级后不得自动显示新手柄或改变原有拖拽行为。
- 关闭贴图功能时，来源应用图标不接受贴图拖拽，不接受新的贴图创建请求，并立即关闭当前所有贴图。
- 新增设置标题、说明、帮助文案、错误反馈和贴图操作文案必须进入 String Catalog，并覆盖项目现有支持的语言。
- 贴图必须读取用户松开鼠标时的实时全局坐标，以该点作为贴图左上角，并仅在越界时夹紧到可见屏幕。
- 贴图交互与拖拽判定属于独立业务层；SwiftUI View 只负责呈现和交互输入。
- MVP 仅支持剪贴板图片记录和指向图片的文件记录。
- 文本、代码、链接、颜色和非图片文件在 MVP 中不启用来源图标贴图拖拽。
- 贴图仅在当前 Clipaste 运行会话中存在；退出应用后全部消失，下次启动不恢复。
- 每张贴图的右上角提供本地化无关的关闭图标按钮，用户可单独关闭贴图。
- 贴图窗口支持在屏幕上任意拖动和放大缩小。
- 贴图窗口四周的系统缩放边缘不得被窗口移动手势覆盖；实时缩放期间不得重入修改窗口尺寸约束。
- 贴图缩放时必须锁定原图宽高比，不允许拉伸变形。
- 贴图仅在创建时所在的 macOS Space 中可见，在该 Space 内始终浮于普通应用窗口上方，不跟随用户切换到其他 Space。
- 右上角关闭按钮始终可见，常态使用弱化的半透明材质，悬停时增强对比度。
- 贴图初始尺寸按用户选择的原图比例计算，默认 100%；过大时仅等比缩小到当前显示器可见区域以内，过小时等比放大到可操作尺寸。
- 同一运行会话内允许同时存在多张贴图，每张贴图拥有独立窗口、位置、尺寸和关闭生命周期。
- 不设置人为数量上限；单张贴图关闭后必须立即释放其窗口与图片资源。
- 新增状态类使用 `@Observable`，不新增 `ObservableObject`。
- 不引入第三方依赖，不使用已废弃 API。
- 大图、超大文本或失效文件不得阻塞主线程，失败时不创建空白贴图。
- 文件 I/O、图片尺寸探测和下采样/解码必须在主线程之外执行；主线程仅负责轻量状态与窗口更新。
- 贴图复用现有有成本上限的图片缓存，不对同一条记录和相同目标像素尺寸重复解码。
- 贴图渲染数据按屏幕需求下采样，最长边不超过 4096 像素。
- 关闭总开关时必须取消未完成的贴图加载任务，防止关闭后延迟创建窗口。

## Acceptance Criteria

- [ ] 用户可从水平卡片和纵向列表发起贴屏操作。
- [ ] 剪贴板图片和图片文件记录在功能开启后可从来源应用图标发起贴图，其他内容类型的图标保持原行为。
- [ ] 高级设置中存在可持久化的贴图功能开关；关闭时来源应用图标不再接受贴图拖拽，现有普通拖拽不受影响。
- [ ] 高级设置中存在 25%–100% 的贴图初始尺寸比例设置，默认 100%，并覆盖全部支持语言。
- [ ] 全新安装和版本升级后贴图开关均默认为关闭，只在用户主动开启后生效。
- [ ] 关闭高级设置开关时，已打开的贴图全部关闭并释放资源。
- [ ] 所有新增用户可见文案均使用 String Catalog 键，不存在英文硬编码占位文本。
- [ ] 贴图左上角与实时鼠标松开点一致；仅在贴图会越界时移动到最近的可见位置。
- [ ] 用户可拖动贴图到任意显示器，并可通过窗口边缘或角放大缩小。
- [ ] 贴图仅显示在创建它的当前 Space，不随 Space 切换跨工作区常驻。
- [ ] 任意缩放后贴图的宽高比与原图一致，且有最小可操作尺寸和不超出当前显示器可见范围的最大尺寸。
- [ ] 连续快速放大缩小及缩放时跨显示器不会造成崩溃或窗口约束重入。
- [ ] 右上角关闭图标只关闭当前贴图，不删除原始历史记录或图片文件。
- [ ] 关闭图标按钮始终可发现，支持工具提示、VoiceOver 标签和键盘激活。
- [ ] 用户可连续创建多张贴图，关闭任意一张不影响其他贴图。
- [ ] 贴图关闭后，贴图管理器不再持有对应窗口和图片资源。
- [ ] 退出应用并重新启动后，上一次会话的贴图不自动恢复。
- [ ] 对支持的内容类型，贴图正确显示清晰内容；数据加载失败时给出本地化反馈。
- [ ] 超大图片或图片文件的读取与解码不阻塞主线程，拖拽结束后历史面板仍可立即滚动和响应。
- [ ] 对同一图片重复贴图时命中共享缓存；关闭贴图或总开关后无多余加载任务继续创建窗口。
- [ ] 拖到支持的第三方应用时仍传递原始内容，不额外创建贴图。
- [ ] 拖到 Clipaste 内部分组时仍只执行收藏或分组移动。
- [ ] 不同内容类型的拖拽意图判定具备可自动化验证的纯逻辑单元测试。

## Out of Scope

- 不在本任务中重写整个历史面板或全量迁移现有 `ClipboardViewModel`。
- 不将贴图数据同步到 CloudKit，除非后续明确需要。
- MVP 不渲染文本、代码、链接、颜色或普通文件贴图。
