# 修复收藏补同步并优化移动端分组加载

## Goal

确保 macOS 本地库中的历史收藏能够一次性补入 Production CloudKit，并让 iOS 在切换收藏、文本、链接、图片及自定义分组时快速呈现可用内容，同时明确展示仍在加载的状态，避免把未完成加载误认为空分组。

## Background

- macOS 当前 Production 云库包含 533 条记录，但没有 `isPinned = true` 的记录。
- macOS 独立本地库包含 203 条记录，其中 1 条为收藏；该收藏的 `contentHash` 在云库中不存在。
- macOS 启动流程只调用 `importLegacyStoreIfNeeded(into:)`，不会补合并 `clipboard-local.store`；完整跨路由合并仅在用户切换同步开关时执行。
- iOS “收藏”直接查询 `ClipboardRecord.isPinned`，记录未进入云库时该分组必然为空。
- iOS 过滤范围切换会清空没有精确缓存的列表；启动快照没有写入 `rowsByFilter[.all]`，因此不能作为过滤范围的即时回退。
- iOS `refresh()` 在发布当前范围的 items 前，顺序执行计数、分组读取、items 读取、包含图片负载的键盘快照读取与快照落盘，扩大了空白等待时间。

## Requirements

- R1. macOS 在云同步启用时执行一次可重试的本地收藏补偿迁移，只迁移本地库中的收藏记录，不上传全部旧历史。
- R2. 补偿迁移必须保留完整 item 内容、`isPinned`、标题、来源信息及分组字段，并使用现有按 `contentHash` 合并语义，避免制造重复记录。
- R3. 仅在迁移成功后记录完成标记；失败时保留重试能力并进入同步诊断信息。
- R4. iOS 切换过滤范围时优先显示启动缓存或“全部”缓存可推导出的内容，再异步刷新该范围的完整结果。
- R5. iOS 当前范围没有可显示缓存且请求未完成时，显示本地化加载状态，不显示空内容提示。
- R6. iOS 当前范围已有缓存内容时保持列表可交互，不用阻塞式遮罩覆盖列表。
- R6.1. 当前范围已有缓存但仍在刷新时，在分组栏展示小型进度指示；当前范围无缓存时，列表中央显示本地化“正在加载…”。
- R7. iOS 当前范围的 items 获取完成后立即发布；键盘快照刷新不得阻塞列表首屏，并应合并重复刷新请求。
- R8. 保持现有 `@Observable` MVVM 边界；View 只渲染加载状态并转发交互，数据库与迁移逻辑留在 Store/Runtime 层。
- R9. 不新增第三方依赖，不改动用户现有的 iOS 工程版本号未提交修改。

## Acceptance Criteria

- [x] AC1. 在云同步启用、local store 有收藏且 cloud store 无对应记录时，首次补偿后 cloud store 出现该记录且 `isPinned = true`。
- [x] AC2. 本地非收藏旧历史不会因补偿迁移被上传；重复启动不会重复导入或产生重复记录。
- [x] AC3. 补偿失败不会写完成标记，诊断中可看到失败原因，后续启动仍会重试。
- [x] AC4. iOS 从“全部”切换到收藏/文本/链接/图片/自定义分组时，有可推导缓存便立即显示；无缓存时显示“正在加载”而非空分组提示。
- [x] AC5. 过滤范围 items 返回后无需等待键盘图片快照读取和文件写入即可显示。
- [x] AC6. 快速连续切换过滤范围不会发布过期结果，加载状态最终归零，列表与选择范围一致。
- [x] AC7. macOS Debug clean build 与相关迁移测试通过；iOS Debug Simulator build 通过，并验证加载态文案的中英文显示。
- [x] AC8. 两个仓库均通过 `git diff --check`，且不覆盖用户已有的 iOS `project.pbxproj` 修改。

## Out of Scope

- 不改变 CloudKit 容器、Production schema 或同步服务提供方。
- 不重做移动端列表视觉样式，不增加骨架屏动画。
- 不把全部历史记录预加载进内存；仍保留分页和范围查询。
